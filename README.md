## 📖 使用說明

### 1. 讀取 PDF 與自動初始化
- 在 Chrome 瀏覽器開啟欲研讀的本機（`file://`）或線上 PDF 檔案。
- 開啟側欄點擊「重新讀取」，擴充功能會自動擷取當前頁碼與頁面文字。
- 當啟用「完整 PDF」並選定特定「專案」時，擴充功能會在**背景分頁**自動將 PDF 注入到該專案的「資料來源」中：
  - 期間側欄會暫時收起舊訊息，顯示橙色狀態文字與加載動畫（「正在同步至專案資料來源…」）。
  - 當 ChatGPT 索引完成後，側欄會自動切換為就緒狀態並平滑載入歷史記錄。

### 2. 高速問答模式
- 初始化成功後，後續的每一次對話**不再重複上傳整份 PDF**，僅傳送目前頁碼、當頁摘要與你的問題。
- ChatGPT 會直接引用專案已索引的資料來源進行回答，省去重複上傳檔案的漫長冷啟動，實現秒級回應。

### 3. 後端模式切換
- **自動 · Chat → Work**：日常問答使用標準 Chat，超出限制或特定需求時自動切換。
- **僅 Chat** 或 **僅 Work**：鎖定使用特定模式。

### 4. 專案選擇
- 點擊設定圖示（⋯），在「專案」下拉選單中可選取你的 ChatGPT Projects。
- 同一專案下的多輪對話將共享相同的專案資料來源。

### 5. 上下文附加控制
- **完整 PDF**：控制是否將檔案納入專案資料來源（或聊天附件）。
- **頁面文字**：自動擷取目前 Chrome PDF 閱讀器可視頁的純文字一併送出。
- **頁面畫面**：可選附加目前頁面截圖，適合包含圖表、公式或排版結構的文檔。

### 6. 歷史記錄管理
- 側欄對話會自動按照「PDF 網址 + 專案」獨立封存於本機。
- 收起或重新開啟同一份 PDF 時會自動接續對話。
- 也可在設定中的「歷史記錄」選單隨時切換查看其他 PDF 的對話記錄。

### 7. 快捷鍵
- <kbd>Ctrl</kbd> + <kbd>Enter</kbd>：快速傳送訊息。

## 安裝

1. 在 Chrome 開啟 `chrome://extensions/`。
2. 開啟右上角「開發人員模式」。
3. 點「載入未封裝項目」，選擇本資料夾 `pdf-chat-sidebar`（安裝後名稱為 `HiiroSideChat`）。
4. 在這個擴充功能的「詳細資料」中開啟「允許存取檔案網址」。
5. 第一次使用前，在普通 Chrome 分頁登入 [ChatGPT](https://chatgpt.com/)。

## 未封裝、ZIP 與 CRX

- `pdf-chat-sidebar/` 是開發用的未封裝目錄；在 `chrome://extensions` 以「載入未封裝項目」安裝，修改檔案後重新載入即可測試。
- `.zip` 只是方便傳送與備份的壓縮檔；Chrome 不能把它當成已簽署擴充功能，需先解壓再載入未封裝目錄。
- `.crx` 是由 Chrome 使用私鑰簽署的封裝檔；更新時必須沿用同一份 `.pem`，才能維持相同的擴充功能 ID。

請妥善備份 `pdf-chat-sidebar.pem`，不要公開或放進分享用 ZIP。一般個人版 Chrome 可能阻擋直接安裝 Chrome Web Store 以外的 CRX；此時仍需使用開發人員模式載入未封裝目錄，或正式發佈到 Chrome Web Store。

## 使用

1. 用 Chrome 內建 PDF Viewer 開啟本地 PDF。
2. 點擊擴充功能圖示開啟側欄。
3. 點入輸入框；擴充功能會預先讀取目前頁面。
4. 輸入問題，按「傳送」或 `Ctrl+Enter`。
5. 傳送前會重新讀取一次頁碼。若已選專案，完整 PDF 只在專案資料來源缺少它時上傳；當頁文字與畫面則隨問題更新。
6. 回答完成後會以打字效果逐步顯示於側欄；「開啟 ChatGPT」可顯示原始對話。
7. 收起或關閉側欄不會清除內容；重新打開同一 PDF 時會恢復記錄。也可從「設定 → 歷史記錄」查看最近的其他 PDF 對話。

側欄不顯示 ChatGPT 生成途中可能撤回的草稿。等待期間顯示動畫；回答完成並取得原始 Markdown／LaTeX 後，再用短暫的打字效果逐步呈現。首次完成時會嘗試把 ChatGPT 對話重新命名為 PDF 檔名。

普通 Chat 模式仍需要一個已登入的非作用中 `chatgpt.com` 分頁承載官方網頁會話，但擴充功能不會主動切換到它。完全不建立網頁分頁只能改用 API，屆時不會消耗普通 Chat 訊息額度。

## Chat／Work 應急切換

「後端」選單提供：

- `自動 · Chat → Work`：平時使用普通 Chat，只有網頁明確顯示用量限制且沒有部分回答時才改送 Work。
- `自動 · Work → Chat`：反向的故障轉移。
- `僅 Chat`、`僅 Work`：停用自動切換。

Chat 與 Work 分別維護專用的背景分頁和 conversation URL。切換時會附上當前 PDF 上下文、原始問題與最近相關對話。回答標題會顯示 `Chat`、`Work` 或 `自動切換`。

若使用專案資料來源，自動切換至另一後端時不必重傳完整 PDF；兩個後端的專案對話都使用同一份來源。未選專案時，完整 PDF 仍會在另一後端的專用對話中各上傳一次。

## 依 PDF 自動歸檔到專案

擴充功能會在本機保存「PDF 檔案網址 → Chat／Work 對話網址」對應。切換回讀過的 PDF 時會自動續接該文件原本的對話；首次閱讀另一份 PDF 時則建立另一個對話。這是事件發生時即時歸檔，不依賴定時任務。

側欄顯示的問答也會另存於 Chrome 本機儲存空間，依 PDF 與所選專案分開。它只保存安裝 v1.5.1 後由側欄收發的內容；既有 ChatGPT 對話仍由 ChatGPT 自己保存，不會被反向完整匯入側欄。清除擴充功能資料或移除擴充功能會清除這份本機顯示記錄。

如果希望對話集中整理，先在 ChatGPT 建立 Project（繁體介面稱為「專案」，例如 `HiiroSideChat`），再從右上角設定的「專案」下拉選擇。初始化會檢查該專案的「資料來源」，只在同名 PDF 不存在時上傳；此後尚未有歷史對話的新 PDF 會從該專案內開始，已歸檔的 PDF 仍直接續接原對話。

擴充功能不再調整推理強度，而是完全跟隨承載對話的 ChatGPT 分頁設定，避免官方滑桿介面改動阻斷提問。

每份 PDF 第一次建立的 Chat／Work 對話會直接從所選專案開始，並記住 PDF、後端與專案的對應；更換專案時不會沿用舊專案裡的對話。這比使用定時任務事後分類可靠，因為專案負責整理相關聊天與共享來源，而定時任務是用來按時間再次執行工作。

側欄設定可調整 14–20px 對話字體；回答區與載入動畫使用白色背景，文件列和輸入區保留米白／橙色配色。

逾時、網路錯誤或一般頁面錯誤不會觸發故障轉移，以免同一問題在兩邊重複送出。如果原後端已有部分回答，也不會自動重送。

首次使用 Work 時，網頁介面可能無法被可靠地自動切換。此時點「開啟 Work」，在該專用分頁手動選擇一次 Work，再回到 PDF 重試。

## 權限與限制

- `file:///*`：讀取你目前打開的本地 PDF。Chrome 仍要求你手動開啟「允許存取檔案網址」。
- `debugger`：短暫讀取 Chrome PDF Viewer 的目前頁碼；每次擷取後立即斷開。Chrome 可能短暫顯示偵錯提示列。
- `https://chatgpt.com/*`：在 Chat／Work 兩個專用 ChatGPT 分頁填入問題並讀回回答。
- 擴充功能不讀取或儲存 ChatGPT Cookie；登入由正常 `chatgpt.com` 分頁管理。
- ChatGPT 網頁改版後，`chatgpt-bridge.js` 的元素選擇器可能需要更新。
- 掃描版 PDF 可能沒有可抽取文字，但頁面畫面仍可附加。
- 目前文字解析以本地 `file://` PDF 為主。
- 回答中的 KaTeX／MathML 公式會優先由 `application/x-tex` annotation 還原成 `$...$` 或 `$$...$$`，再於側欄重新渲染。
- 回答正式完成時會攔截 ChatGPT「複製回答」產生的原始 Markdown／LaTeX 作最終校正；攔截不會覆蓋系統剪貼簿，也不影響使用者平常的複製操作。

## 排錯

- 「頁碼未取得」：關閉該 PDF 分頁的 DevTools，重新點擊側欄的重新整理按鈕。
- 出現 `pdf-viewer element not found`：更新至 0.2.1 並在 `chrome://extensions/` 重新載入擴充功能；此版會搜尋 Chrome 隔離的 PDF Viewer 子目標。
- 「讀取 PDF 失敗」：確認擴充功能的「允許存取檔案網址」已開啟。
- 「ChatGPT 尚未登入」：點「開啟 ChatGPT」並登入。
- 找不到輸入框或傳送按鈕：ChatGPT 介面可能已更新，先在背景分頁確認頁面正常，再更新 `chatgpt-bridge.js` 的選擇器。
